[운영 지침](brief-workflow.md)의 세 단계 리서치에 쓰는 출발점입니다. 고정 목록은 확인해야 할 최소 범위이며 전체 시장 목록이 아닙니다. 매번 목록 밖 신제품 탐색과 최근 7일 재확인까지 수행합니다.

아래 경로는 2026-09-17 리서치에서 확인하거나 접근을 시도한 공식 경로를 중심으로 정리했습니다. 페이지 구조·주소·제품명이 바뀔 수 있습니다. 오래된 주소나 메뉴만 읽힌 페이지를 근거로 `새 소식 없음`이라고 결론 내리지 말고, 공식 홈페이지의 현재 메뉴·발표문·문서 링크를 따라 보완합니다. 접근이 안 되면 실패 범위를 기록합니다.

## 2단계 — 목록 밖의 새 제품과 제작 방식을 찾기

고정 목록과 별개로 아래 주제를 회사명 제한 없이 탐색합니다. 한국어·영어와 필요한 중국어 검색을 조합하고, 기간은 기본 수집 범위에서 시작해 최근 7일까지 넓힙니다. 독립적인 출처 조사는 병행할 수 있지만 세 단계의 결과를 모두 대조한 뒤 편성합니다.

| 탐색 주제 | 검색·발견의 예 |
|---|---|
| 이미지·영상·음악·음성 | 새 모델 버전, 실시간 영상 편집, 아바타·캐릭터 대화, 음악 생성·편집, 음성·전화 제품 |
| 코딩·에이전트·제작 업무 | 새 에이전트 플랫폼, 장기 작업, 문서·슬라이드·디자인, 편집 도구 연동, 새 API·하네스 |
| 마케팅·사업 운영 | 광고 제작·집행, 고객 응대·CRM, 쇼핑, 콘텐츠 사업 운영, 시장 조사·성과 분석 |
| 국내·중국 상업 사례와 시장 | 브랜드·캐릭터 IP, 가상 인플루언서, AI 숏폼·숏드라마, 공모·캠페인, 인프라·규제·보안 |

검색·SNS·전문 매체·제품 모음은 후보 발견에 사용할 수 있습니다. 발견한 이름으로 개발사 제품 페이지, 발표문, 공식 계정, API 문서·저장소를 찾아 다시 확인합니다. 재인용 글만 여러 개 읽었다고 검증된 출처가 여러 개인 것으로 세지 않습니다. 공개된 기술·제품 조건은 1차 출처를 우선하고, 1차 출처를 찾지 못했다면 확인한 보도의 범위와 한계를 밝힙니다.

채택할 만한 제품을 발견하면 다음 날에도 찾을 수 있도록 실제 공식 경로를 이 문서의 해당 영역에 추가할 수 있습니다. 후보 수를 채우기 위해 검증되지 않은 경로나 새로운 브랜드 이름을 넣지 않습니다. Pion처럼 새로 발견한 사건을 오늘 출시로 바꾸지 않고 원발표일을 확인합니다.

## 3단계 — 최근 7일 누락과 예정된 출시를 다시 확인

1. 기본 수집 마감 기준 최근 7일의 공식 발표·릴리스·제품별 검색을 다시 봅니다. 고정 목록에서 발견한 새 모델명과 2단계의 새 제품명도 포함합니다.
2. 최근 브리프에서 예고·베타·대기 명단·순차 적용·요금/API 미확인 항목을 추려 공식 제품·문서에서 현재 상태를 확인합니다. 예정 날짜가 왔다는 이유만으로 실제 출시를 확정하지 않습니다.
3. 전체 `briefs/`에서 제품명·이전 이름·모델 버전·원문 URL을 찾아 이미 다룬 사건인지 확인합니다. 다른 매체의 재보도나 SNS 시연만 바뀐 같은 사건은 제외합니다.
4. 처음 다루는 유용한 소식이 최근 7일 안이지만 기본 범위 밖이면 원발표일과 `누락 보완`을 제목에 붙입니다. 이미 다룬 사건의 실제 제공·지역/계정 확대·API 개방·가격 공개 등 변화라면 새 변화의 날짜와 `후속`을 적습니다.
5. 초안을 쓴 뒤 후보 목록과 다시 대조합니다. 본문 8~12개는 편집 목표이며 상한이 아닙니다. 검증한 독립 사건을 개수 때문에 버리지 말고, 주요 또는 짧은 카드로 남깁니다. 중복·실무 관련성 부족·오래된 소식·검증 실패로 제외한 이유는 작업 메모에 기록합니다.

## 조사 완료 기록

후보별로 발견 단계, 제품·모델 버전, 원발표일과 시각/시간대 확인 여부, 직접 읽은 URL, 현재 제공 범위, 이전 브리프 대조, 채택·제외 이유를 기록합니다. 로컬 메모를 다음 실행기가 읽을 수 있다고 가정하지 않습니다. 다음 실행에 필요한 공개 사실·출처·상태는 최종 브리프나 이 경로 문서에 남깁니다.

헤더에는 고정 경로 스윕과 함께 `> 스윕: 목록 밖 탐색 …`, `> 스윕: 최근 7일 누락·후속 …` 형태로 확인 범위와 결과를 짧게 남깁니다. 후보가 없을 때도 실제로 조사한 범위 안에서만 미확인이라고 쓰고, 접근하지 못한 페이지는 별도로 표시합니다. 확인 날짜만으로 발표일을 대신하지 않습니다.
