# AI Pulse · 원본

브리프 원문·작성 지침·웹사이트 생성 코드를 보관합니다. **다른 컴퓨터에서도 이 저장소의 `source` 브랜치를 읽고 새 브리프를 이어서 만들 수 있습니다.** 예전 컴퓨터의 별도 원본 폴더나 운영 프롬프트를 전달받을 필요가 없습니다.

공개 저장소 [`shinnarag/ai-brief`의 `source` 브랜치](https://github.com/shinnarag/ai-brief/tree/source)가 작업 기준입니다. source 브랜치에 변경을 올리면 `.github/workflows/build.yml`이 GitHub 서버에서 빌드·검증하고, [Actions 실행 기록](https://github.com/shinnarag/ai-brief/actions?query=branch%3Asource)에서 결과를 확인할 수 있습니다. 이 검사는 공개 사이트를 교체하지 않습니다.

## 다른 컴퓨터에서 브리프 만들기

웹 조사와 GitHub 파일 읽기·쓰기가 가능한 AI 도구에 아래처럼 요청합니다. 날짜는 실제 대상일로 바꿉니다.

```text
shinnarag/ai-brief의 source 브랜치에서 AGENTS.md와 docs/brief-workflow.md를 읽고,
YYYY-MM-DD 브리프를 작성해 주세요. 웹에서 출처를 확인하고 원문을 source에 저장한 뒤,
해당 커밋의 Actions 결과와 사이트 게시 여부를 구분해 알려 주세요.
```

- [운영 지침](docs/brief-workflow.md): 날짜·리서치·문체·중복 검사·저장·검증 순서.
- [작성 템플릿](docs/brief-template.md): 현재 사이트 빌더와 맞는 Markdown 형식.
- [AI 작업 안내](AGENTS.md): 이 저장소에서 먼저 읽을 기준.

GitHub 파일을 직접 편집하는 도구라면 로컬 복제 없이 진행할 수 있습니다. 원래 컴퓨터의 전원은 필요하지 않습니다. 다만 이 지침을 실행할 AI 도구는 있어야 하며, GitHub 연결이나 Markdown 파일만으로 정시 무인 생성이 시작되지는 않습니다.

## 현재 상태

- 이 Mac에서 찾은 기존 사이트 코드에 사용자가 추가한 최신 브리프를 반영한 **로컬 빌드·미리보기 환경**입니다.
- 2026-09-16 기준 브리프 **44개**, 최신 날짜 **2026-09-16**입니다. 이후 최신 날짜는 `briefs/` 목록에서 확인합니다.
- 월별 달력과 비스킷 59개는 공개 사이트에 맞춰 동기화했습니다. 생성 코드는 이전 Mac 버전을 바탕으로 보완했습니다. 새 브리프 작성은 저장소의 운영 지침을 따르며, 과거 box 코드 확보를 기다릴 필요가 없습니다.
- 현재 지원: 지침을 읽는 AI의 수동 리서치·작성, 환경 점검, 정적 사이트 빌드, 산출물 기본 검증, 로컬 미리보기, 원본 변경 시 GitHub Actions 빌드 검사. [첫 GitHub 서버 빌드](https://github.com/shinnarag/ai-brief/actions/runs/35069622027)는 2026-09-16에 성공했습니다.
- 아직 미구현: 뉴스 수집·AI 작성의 무인 실행기, 실행 상태/재시도, 예약 실행, 이 원본에서 Pages로 자동 배포, 외부 알림.
- 기존 Mac 운영 폴더는 수정하지 않았고 `.env`, 인증 정보, 배포·알림 스크립트, 예약 설정은 복사하지 않았습니다.

## 실행

이 폴더에서 실행합니다. 명령은 폴더 경로에 의존하지 않아 나중에 다른 위치나 CI에서도 사용할 수 있습니다.

```bash
python3 scripts/local.py check
python3 scripts/local.py build
python3 scripts/local.py serve
```

미리보기: <http://127.0.0.1:8765/>. 종료는 `Ctrl+C`입니다. 포트가 사용 중이면 `python3 scripts/local.py serve --port 8766`을 사용합니다.

별도 Python 환경이 필요한 경우:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/local.py build
.venv/bin/python scripts/local.py serve
```

Node.js도 필요합니다. 확인한 환경은 Python 3.14.3, Node.js 24.14.0, Markdown 3.10.2입니다. GitHub Ubuntu 실행 서버에서 의존성 설치와 브리프 44개 빌드·검증을 확인했습니다.

`build`는 이 폴더의 `site/public/`을 다시 생성하고 `logs/`에 비스킷 후보를 씁니다. 원본 JS를 빌드할 때 수정하던 기존 동작은 제거했습니다. 검증은 주요 페이지·모든 브리프 페이지 존재, JSON 파싱, 최신 페이지 연결, JS 문법, 컴퓨터 고유 경로 노출을 확인합니다. 콘텐츠 사실성이나 전체 링크 품질까지 검증하는 단계는 아닙니다.

2026-09-16 브리프 반영 시 8/19~9/16의 평일 21개, 파일명·본문·수집 날짜의 일치와 기본 형식을 확인했습니다. 9/14의 Amodei Top 5가 본문과 표현이 달라 짧은 중복 카드를 만들던 연결 처리도 보완했습니다. 짧은 인물·제품명이 정확히 같고, 본문 후보가 하나이며, 추가 문맥 단어까지 공유할 때만 기존 본문을 연결합니다. 원본 브리프 44개의 내용은 수정하지 않았습니다.

공개본 화면 보존 검사: CSS·화면 JS·비스킷 JS를 공개본에서 가져왔고, 월별 달력의 생성 HTML 구조는 공개본과 같습니다. 7~9월 달력의 44개 링크, 최신 월 자동 스크롤, 날짜 요약, 비스킷 사전 59개, 9/16 홈 카드 6개 및 관련 용어 7개를 확인했습니다. 용어 자동 연결의 Python 최신 원본은 공개되지 않아 추가 용어의 패턴은 공개 사전을 바탕으로 복원했습니다. 과거 모든 문장의 강조 위치까지 동일하다고 보장하는 것은 아닙니다.

## 다음 순서

1. **지침으로 다음 브리프 작성:** 이 저장소의 운영 지침과 최근 브리프를 읽고 리서치 → 작성 → 검수 → source 저장 → Actions 검사를 수행합니다. 다른 컴퓨터 또는 클라우드 AI 환경에서도 같은 절차를 사용합니다.
2. **사이트 게시 연결:** 기존 배포 주체를 확인하고, source에서 빌드한 `site/public/`만 Pages에 전달하도록 전환합니다. 자세한 내용은 [GitHub 원본 관리 계획](docs/github-source-plan.md)을 따릅니다.
3. **무인 생성 연결:** 필요할 때 이 지침을 사용하는 AI 실행기와 웹 조사·인증·영속 상태·재시도·예약을 연결합니다. 클라우드 실행이면 개인 컴퓨터 전원이 필요하지 않습니다.
4. **중복 운영 방지:** 기존 예약과 새 예약이 동시에 발행하지 않도록 운영 주체를 하나로 정하고 실제 페이지 반영을 확인합니다. 기존 box 자료는 필요할 경우 비교용으로 확보할 수 있지만 새 수동 작성의 선행조건은 아닙니다.

## 원본과 규칙의 구분

- `docs/brief-workflow.md`: 현재 저장소에서 따르는 독립 운영 기준입니다. 제공된 인계서의 편집 기준을 현재 코드에 맞게 정리했고, 과거 자동화의 미확인 상태를 그대로 이어받았다고 가정하지 않습니다.
- `AGENTS.md`, `docs/brief-template.md`: 운영 지침 진입점과 작성 양식입니다.
- `references/HANDOFF-FOR-SUCCESSOR.md`: 사용자가 제공한 2026-09-16 인계서. 검토 자료이며 이 파일을 복사했다고 자동 실행하지 않습니다.
- `references/legacy-prompt.md`, `legacy-WATCHLIST.md`, `legacy-README.md`: 이전 Mac 버전의 비교 자료입니다. 현재 수집 프롬프트로 사용하지 않습니다. 과거 절대 경로와 오래된 규칙이 남아 있습니다.
- `source-manifest.json`: 최초 가져온 파일의 출처와 원본 SHA-256, 이후 추가한 브리프 목록과 확인 시점의 SHA-256. `site/build.py`는 가져온 후 위에 기록한 변경을 적용했습니다.

새 브리프는 AI가 이 지침에 따라 작성할 수 있습니다. 예약 무인 생성과 source에서 실제 사이트로 배포하는 단계는 아직 연결하지 않았습니다.
